# 单 Agent Skill

## 适用范围

当当前任务属于以下任一情况时加载本 skill：

- 工作区只有一个主要 agent 负责完成任务。
- 当前节点是最终回答节点，主要职责是直接回应用户。
- 协作链不是本次任务重点，或 runtime 不依赖额外的 orchestrator 上下文文件。

如果当前工作区存在多个协作节点、明确的上下游 handoff、router / planner / worker 分工，优先改用 `multi-agent-skill`。

## 单 Agent 规则

- 默认将当前 agent 视为直接面向用户的回答者，而不是流程中间节点。
- 默认不要要求输出 `next_agent`、`next_task`、`handoff` 等路由字段，除非当前工作区契约明确要求。
- 不要把回答写成流程汇报、状态回执、阶段性播报或“本轮执行摘要”。
- 不要为了“结构完整”强制输出 `steps`、`skills_used`、`notes` 等对用户没有直接价值的字段。
- 当用户问题可直接回答时，先回答可回答的部分，再补充边界、假设或必要追问。
- 如果信息不足，不要先进入空泛澄清流程；应先给出可用的初步答案，再明确指出缺失项。

## 单 Agent Prompt 重点

为单 agent 编写 prompt 时，优先明确：

- 该 agent 是最终回答者还是主要执行者。
- 它面向的是最终用户，而不是上游调度器。
- 它应输出什么样的最终结果，而不是内部协作痕迹。
- 当缺少外部上下文时，应如何在能力边界内仍然给出高质量回答。
- 当任务是分析、解释、建议、问答时，应优先直接给结论或可执行建议。

## 单 Agent 完成标准

以下条件同时满足时，才算完成：

- prompt 明确表达该节点直接面向用户。
- 默认不暴露无意义的 handoff 字段。
- 最终回答优先于流程展示。
- 输出内容自然、具体、可直接使用。
- 与当前 runtime contract 保持兼容，而不是仅仅看起来像一个“完整 agent 模板”。
